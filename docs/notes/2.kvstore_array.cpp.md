# 第 2 步：kvstore_array.cpp 数组引擎

> 这一步实现最简单的存储引擎：一块连续内存 + 线性查找。所有操作都是 O(n)。
> 目的：先跑通整个流程，感受数据结构的接口长什么样，后面再换更高效的引擎。

---

## 模板代码

```cpp
// ============================================================
// kvstore_array.cpp —— array 引擎实现
// 数据结构：一块连续内存 + 线性查找。set/get/del/mod 全是 O(n)
// ============================================================
#include "kvstore.hpp"

// 头文件里 extern 声明的全局引擎，在这里"定义"它（分配内存）
Array g_array;

// 初始化：分配 KVS_ARRAY_SIZE 个 ArrayItem 的连续内存
int kvstore_array_create(Array *arr) {
    if (!arr) return -1;
    arr->table = new ArrayItem[KVS_ARRAY_SIZE]();   // ① () 是值初始化
    arr->idx = 0;
    return 0;
}

// 销毁：先释放每一对 key/value，再释放整块 table
void kvstore_array_destroy(Array *arr) {
    if (!arr) return;
    for (int i = 0; i < arr->idx; ++i) {
        delete[] arr->table[i].key;
        delete[] arr->table[i].value;
    }
    delete[] arr->table;
    arr->table = nullptr;
    arr->idx = 0;
}

// set：追加一对 key/value
int kvs_array_set(Array *arr, const char *key, const char *value) {
    if (!arr || !key || !value) return -1;
    if (arr->idx >= KVS_ARRAY_SIZE) return -1;       // 满了

    // ② 为什么要拷贝？调用方的字符串随时可能被覆盖/释放
    char *kcopy = new char[strlen(key) + 1]();        // +1 留给 '\0'
    char *vcopy = new char[strlen(value) + 1]();
    strcpy(kcopy, key);
    strcpy(vcopy, value);

    arr->table[arr->idx].key = kcopy;
    arr->table[arr->idx].value = vcopy;
    arr->idx++;
    return 0;
}

// get：线性扫描，找到返回 value 指针，找不到返回 nullptr
const char *kvs_array_get(Array *arr, const char *key) {
    if (!arr || !key) return nullptr;
    for (int i = 0; i < arr->idx; ++i) {
        if (arr->table[i].key && strcmp(arr->table[i].key, key) == 0) {
            return arr->table[i].value;              // ③ 零拷贝：直接返回内部指针
        }
    }
    return nullptr;
}

// delete：找到后用"最后一项补位"，保持数组紧凑
int kvs_array_delete(Array *arr, const char *key) {
    if (!arr || !key) return -1;
    for (int i = 0; i < arr->idx; ++i) {
        if (strcmp(arr->table[i].key, key) == 0) {
            delete[] arr->table[i].value;
            delete[] arr->table[i].key;
            // ④ 把最后一项移到被删位置，再收缩下标
            arr->table[i] = arr->table[arr->idx - 1];
            arr->table[arr->idx - 1].key = nullptr;   // 防止重复释放
            arr->table[arr->idx - 1].value = nullptr;
            arr->idx--;
            return 0;
        }
    }
    return arr->idx;                                  // ⑤ 找不到：返回 >0
}

// modify：找到 key，换掉它的 value
int kvs_array_modify(Array *arr, const char *key, const char *value) {
    if (!arr || !key || !value) return -1;
    for (int i = 0; i < arr->idx; ++i) {
        if (strcmp(arr->table[i].key, key) == 0) {
            delete[] arr->table[i].value;             // 先释放旧 value
            arr->table[i].value = new char[strlen(value) + 1]();
            strcpy(arr->table[i].value, value);
            return 0;
        }
    }
    return arr->idx;                                  // ⑤ 找不到：返回 >0
}

// count：当前元素个数
int kvs_array_count(Array *arr) {
    if (!arr) return -1;
    return arr->idx;
}

// ---------- 本地测试（不依赖网络层，编译这个文件就能跑） ----------
#if 1
#include <cstdio>
int main() {
    kvstore_array_create(&g_array);

    kvs_array_set(&g_array, "Name", "King");
    kvs_array_set(&g_array, "Age", "18");
    printf("count = %d (expect 2)\n", kvs_array_count(&g_array));
    printf("Name  = %s (expect King)\n", kvs_array_get(&g_array, "Name"));

    kvs_array_modify(&g_array, "Name", "Darren");
    printf("Name  = %s (expect Darren)\n", kvs_array_get(&g_array, "Name"));

    kvs_array_delete(&g_array, "Age");
    printf("count = %d (expect 1)\n", kvs_array_count(&g_array));
    printf("Age   = %s (expect (null))\n", kvs_array_get(&g_array, "Age"));

    kvstore_array_destroy(&g_array);
    return 0;
}
#endif
```

## 核心知识点（对应代码编号）

### ① `new T[n]()` 末尾的括号

`new ArrayItem[KVS_ARRAY_SIZE]()` 末尾的 `()` 是**值初始化**：把每个 `ArrayItem` 的成员清零（`key=nullptr, value=nullptr`）。

**如果不写 `()` 会怎样？**
```cpp
new ArrayItem[KVS_ARRAY_SIZE]    // POD 类型成员是未初始化的垃圾值
```
后面你读 `table[i].key` 就是野指针，程序行为未定义。

**同理：** `new char[strlen(key)+1]()` 末尾的 `()` 保证最后一个字节是 `'\0'`，这样 `strcpy` 之后字符串天然以 `\0` 结尾，安全。

---

### ② 为什么要拷贝 key/value？（面试常问）

假设你不拷贝，直接存调用方传进来的指针：

```cpp
kvs_array_set(&g_array, "Name", "King");
// 指针指向调用方栈上的字符串

... 调用方函数返回，栈帧销毁 ...
// 现在 table[0].key 指向已经回收的内存 → 野指针！
```

**所以必须 `new` 一块新内存，把字符串内容复制过去**——引擎自己持有这份数据的所有权，和调用方生命周期解耦。

这就是为什么后面有 `destroy` 函数：**谁 new 的，谁 delete，引擎负责释放它持有的每一对数据**。

---

### ③ get 返回内部指针（零拷贝）

`kvs_array_get` 直接把 `table[i].value` 返回出去，不拷贝。

- **优点：** 快，零拷贝
- **代价：** 调用方拿到的是**只读**指针（所以返回类型是 `const char*`），不能改它，否则破坏引擎内部数据

这是"读多写少"场景的标准优化。

---

### ④ 删除策略：交换删除

课程原版的 delete 是：把被删位置的 key/value 置 `NULL`，然后 `idx--`——留下一个"空洞"，以后 `set` 直接追加到 `idx`，空洞永远不被复用。

**我写的是交换删除：** 把数组最后一项挪到被删位置，再 `idx--`——数组始终紧凑，没有空洞。

| 对比 | 标记删除（课程原版） | 交换删除（我的版本） |
|---|---|---|
| 空间利用率 | 有空洞，浪费 | 紧凑，无空洞 |
| 元素顺序 | 保持插入顺序 | 最后一项会跑到前面 |
| 适用场景 | 需要按插入顺序遍历 | 不关心顺序，追求紧凑 |

> **注意：** 交换删除后元素**顺序会变**。如果你以后要按插入顺序遍历，就得用课程的标记删除。这是个取舍，面试可以聊。

**防 double free 的细节：**
```cpp
arr->table[arr->idx - 1].key = nullptr;
arr->table[arr->idx - 1].value = nullptr;
```
把最后一项搬走后，原位置必须清空，否则 `destroy` 遍历时会释放两次同一块内存。

---

### ⑤ 返回值约定（整个项目的协议）

```
返回值 < 0  → 参数错误 / 引擎错误（协议层回 ERROR）
返回值 = 0  → 操作成功（协议层回 SUCCESS）
返回值 > 0  → key 不存在（协议层回 NO EXIST）
```

`delete` 和 `modify` 找不到 key 时返回 `arr->idx`（当前元素个数，肯定 >0）。

这个约定**第 3 步写协议层时直接依赖**，现在记住。

## 深入讨论：C++ 内存管理

### 一、`delete[] arr->table;` 到底在做什么？

```cpp
delete[] arr->table;
```

| 部分 | 含义 |
|---|---|
| `arr->table` | 指向一块**连续数组内存**的指针（create 时 `new ArrayItem[1024]` 分配的） |
| `delete[]` | 告诉编译器：这是用 `new[]` 分配的数组，逐个析构后整块释放 |

---

### 二、关键规则：`new[]` 必须配 `delete[]`

回头看你 `create` 函数里是怎么分配的：

```cpp
arr->table = new ArrayItem[KVS_ARRAY_SIZE]();   // 注意这里的 []
```

**分配时用了 `new[]`，释放时必须用 `delete[]`**，这是配对关系，不能换：

```
new T[n]  ←→  delete[] p    // ✅ 正确
new T     ←→  delete p     // ✅ 正确
new T[n]  ←→  delete p    // ❌ 未定义行为（数组用单个 delete 释放）
new T     ←→  delete[] p  // ❌ 未定义行为（单个对象用数组 delete 释放）
```

---

### 三、`delete` 和 `delete[]` 到底差在哪？

对普通类对象，区别是：
- `delete p`：对 **1 个对象**调用析构函数，释放内存
- `delete[] p`：对数组里的 **每一个元素**调用析构函数，再整块释放内存

你的 `ArrayItem` 是纯数据（两个 `char*`），没有析构函数，所以**即使写混了编译器也不会报错，看起来也能跑**——但这是未定义行为（UB），换个类型、换个编译器就可能崩。

> **规则必须守：分配用什么形式，释放就用什么形式。**

---

### 四、为什么不用 `free()`？

C++ 内存管理有两套，**不能混用**：

```
new / delete        // C++ 方式，会调用构造/析构函数
malloc / free       // C 方式，只分配/释放原始字节
```

你的 `create` 用的是 `new[]`，所以必须用 `delete[]`。如果哪天你改成 `malloc`，就要配对 `free`——这也是课程 C 代码里全是 `malloc/free` 的原因（纯 C 没有 new/delete）。

---

### 五、完整的内存生命周期

```cpp
// create：分配
arr->table = new ArrayItem[1024]();   // 向系统要一块能装 1024 个 ArrayItem 的内存

// destroy：释放
for (int i = 0; i < arr->idx; ++i) {
    delete[] arr->table[i].key;       // 先释放每一对 key/value（它们也是 new[] 的）
    delete[] arr->table[i].value;
}
delete[] arr->table;                 // 再释放整块 table 数组本身
```

**顺序很重要：** 先释放数组里每个元素指向的内存，最后释放数组本身。反过来会内存泄漏（数组先释放，里面的 key/value 指针就找不到了）。

## 深入讨论：指针与数组

### 六、怎么知道 `table[i].key` 是 new[] 出来的？

> 这是你问的问题，触到了 C++ 手动内存管理的核心。

**答案：去 `set` 函数里看。**

`table[i].key` 是怎么来的，就怎么释放。翻到你写的 `kvs_array_set`：

```cpp
char *kcopy = new char[strlen(key) + 1]();   // ← 看这里
char *vcopy = new char[strlen(value) + 1]();
strcpy(kcopy, key);
strcpy(vcopy, value);

arr->table[arr->idx].key = kcopy;             // ← key 就是这块内存
arr->table[arr->idx].value = vcopy;
```

`kcopy` 是用 `new char[strlen(key)+1]` 分配的——**注意那个 `[]`，这是 new[]（分配 n 个连续 char）**。所以 destroy 时必须用 `delete[]`。

**规则就是：你在哪个函数用 `new[]` 申请的，就在哪个函数用 `delete[]` 释放。**

编译器不会帮你记，全靠你自己维护这个对应关系。

---

### 七、为什么 key 必须用 `new[]` 而不能用 `new`？

因为 key 是**长度不固定的字符串**：

```cpp
new char                 // 只分配 1 个 char，存不下 "Name"
new char[strlen(key)+1] // 分配 strlen+1 个连续 char，正好存下整个字符串 + '\0'
```

`strlen("Name") = 4`，要存 "Name" 就得分配 5 个 char（4 个字符 + 末尾的 `\0`）。

这就是为什么用 `new[]`——你要的是"一块连续的字符数组"，不是单个字符。

---

### 八、核心概念：指针不携带分配信息

这是你这个问题最该理解的一点：

```cpp
char *p = new char[100];   // p 只是一个地址
delete[] p;                // 对的
```

`p` 这个指针变量本身**只存了一个内存地址**，它不知道：
- 这块内存是用 `new` 还是 `new[]` 分配的
- 这块内存有多大
- 里面存了什么

所以你写 `delete p` 还是 `delete[] p`，编译器**不会报错**，它只能按你写的来。写混了就是未定义行为——对 `char*` 这种没有析构函数的类型，大多数编译器上"碰巧能跑"，但这是侥幸，不是安全。

---

### 九、为什么指针能当数组用？`table[idx]` 寻址原理

> 这也是你问的问题：table 定义的时候只是一个指针，为什么能用下标寻址？

**一句话答案：** `[]` 本来就是指针运算的语法糖。在 C/C++ 里，`p[i]` 和 `*(p + i)` 是完全等价的。

---

#### 图解

你的定义：
```cpp
ArrayItem *table = nullptr;   // table 是个指针，指向一个 ArrayItem
```

但 `create` 时：
```cpp
arr->table = new ArrayItem[1024]();
```

`new ArrayItem[1024]` 做了两件事：
1. 在堆上分配了**一块连续内存**，能装 1024 个 `ArrayItem`
2. 返回这块内存**第一个元素的地址**，存进 `table`

所以 `table` 虽然类型是"指向单个 ArrayItem 的指针"，但它实际指向一块连续数组的开头：

```
table 指针（存的是首元素地址）
   │
   ▼
┌─────────────┬─────────────┬─────────────┬─────────────┐
│  ArrayItem  │  ArrayItem  │  ArrayItem  │  ArrayItem  │ ...
│  table[0]   │  table[1]   │  table[2]   │  table[3]   │
│  key=...    │  key=...    │  key=...    │  key=...    │
└─────────────┴─────────────┴─────────────┴─────────────┘
   ▲              ▲              ▲
   table          table+1       table+2
   （首地址）     （往后跳1个）   （往后跳2个）
```

---

#### `[]` 到底做了什么

```cpp
arr->table[arr->idx].key = kcopy;
```

等价于：
```cpp
*(arr->table + arr->idx).key = kcopy;
```

执行过程：
1. `table + idx`：从 `table` 指向的位置，往后跳 `idx` 个 `ArrayItem` 的大小
2. `*`：解引用，拿到那个位置的 `ArrayItem`
3. `.key`：访问它的 `key` 字段

**关键：指针加法的步长不是 1 字节，而是指针指向类型的大小。**

```cpp
ArrayItem *table;
table + 1;   // 实际地址 += sizeof(ArrayItem)，不是 +1 字节
```

`ArrayItem` 里有两个 `char*`（8+8=16 字节），所以 `table + 1` 实际往后跳 16 字节，正好指向下一个元素。

这就是为什么指针能正确寻址数组。

---

#### 为什么类型是"指向单个"而不是"指向数组"？

C/C++ 的设计就是这样：
- 数组名在表达式里会**退化**成指向首元素的指针
- `new T[n]` 返回的是 `T*`（首元素指针），不是"数组指针"类型
- 编译器**不知道也不关心**你这块内存是 1 个元素还是 1024 个元素——它只知道"这是个 T*"

这就是为什么 `delete[]` 要你手动写 `[]`：
- 编译器不知道这块内存原来分配了多少个元素
- 它只看到一个 `T*`
- `delete[]` 就是在告诉它："这是个数组，析构时要循环 n 次"

---

#### 对比你在 tinywebserver 里用过的

其实你早就见过这个概念，只是没点破：

```cpp
std::vector<char> buffer;
buffer[0] = 'a';     // vector 的 [] 也是同样的原理
```

vector 内部就是一块连续内存 + 首指针 + size，`buffer[i]` 本质就是 `*(data + i)`。只不过 vector 帮你封装了，你看不到指针。

---

### 十、现代 C++ 怎么避免手动内存管理的痛苦？

你以后不会想这么累——现代 C++ 根本不手动 new/delete：

```cpp
// 现在（课程教学写法，手动管理）
char *key = new char[strlen(input) + 1];
...
delete[] key;

// 现代 C++ 写法（编译器自动管理）
std::string key = input;       // 析构时自动释放，不用你管
```

课程用 `char*` + 手动 new/delete，是为了**让你看到内存分配释放的全过程**，理解底层发生了什么。等你理解了，实际项目里用 `std::string` 和 `std::vector`，这些细节编译器帮你做。
