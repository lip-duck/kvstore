# 第 1 步：kvstore.hpp 头文件

> 本文件是整个项目的"总纲"：定义数据结构、宏开关、函数声明。所有 .cpp 文件都 #include 它。

---

## 模板代码

```cpp
// ============================================================
// kvstore.hpp —— KV 存储项目 · 第 1 步：头文件（C++ 版）
// 本文件只做 4 件事：宏开关 / 连接对象 / array 引擎结构 / 函数声明
// ============================================================

#ifndef __KVSTORE_HPP__            // ① include guard：防止头文件被重复包含
#define __KVSTORE_HPP__

#include <cstddef>                 // ② C++ 版的 C 标准头文件（size_t 等）
#include <cstdio>                  //    snprintf / printf
#include <cstring>                 //    memset / strlen / strcpy
#include <cassert>                 //    assert
#include <functional>              //    std::function（模板暂未用，后续演进预留）

// ---------------- ③ 宏开关：决定系统编译成什么形态 ----------------
#define BUFFER_LENGTH  512         // 每个连接的收发缓冲区长度（字节）

// 网络层选择：同一套业务代码，换网络模型只改这一个宏
#define NETWORK_EPOLL    0
#define NETWORK_NTYCO    1
#define NETWORK_IOURING  2
#define ENABLE_NETWORK_SELECT  NETWORK_EPOLL   // 当前先只用 epoll

// 引擎开关：先只开 array，其余留 0（后续逐个打开）
#define ENABLE_ARRAY_KVENGINE   1
#define ENABLE_HASH_KVENGINE    0
#define ENABLE_RBTREE_KVENGINE  0

// ---------------- ④ 连接对象：每个 TCP 连接对应一个 ----------------
struct ConnItem {
    int fd = -1;                                  // 该连接的文件描述符
    char rbuffer[BUFFER_LENGTH] = {0};            // 收缓冲区
    int  rlen = 0;                                // 已收到多少字节
    char wbuffer[BUFFER_LENGTH] = {0};            // 发缓冲区
    int  wlen = 0;                                // 待发送多少字节

    // ⑤ 回调函数指针：epoll 就绪后调用的处理函数
    using Callback = int (*)(int fd);             // 类型别名：指向"入参 int、返回 int"的函数
    Callback recv_callback = nullptr;             // 读事件回调
    Callback send_callback = nullptr;             // 写事件回调
};

// ---------------- ⑥ array 引擎 ----------------
constexpr int KVS_ARRAY_SIZE = 1024;              // ⑦ 编译期常量：最多存 1024 对

struct ArrayItem {                                // 一对 key/value
    char *key = nullptr;                          // 堆上分配的字符串（长度不固定，所以用指针）
    char *value = nullptr;
};

struct Array {
    ArrayItem *table = nullptr;                   // 指向堆上一块连续内存（容量 KVS_ARRAY_SIZE）
    int idx = 0;                                  // 当前已用下标（也等于元素个数）
};

extern Array g_array;                             // ⑧ 全局唯一引擎实例（定义在 .cpp 里）

// ---------------- ⑨ 引擎接口声明（先只声明 array） ----------------
int  kvstore_array_create(Array *arr);                        // 初始化：分配 table 内存
void kvstore_array_destroy(Array *arr);                       // 释放
int  kvs_array_set(Array *arr, const char *key, const char *value);
const char *kvs_array_get(Array *arr, const char *key);       // ⑩ 返回 const char*：只读、零拷贝
int  kvs_array_delete(Array *arr, const char *key);
int  kvs_array_modify(Array *arr, const char *key, const char *value);
int  kvs_array_count(Array *arr);

// ---------------- 网络层 & 协议层 ----------------
int epoll_entry();                                // epoll 主循环入口（第 4 步写）
int kvstore_request(ConnItem *item);              // 协议解析入口（第 3 步写）

#endif // __KVSTORE_HPP__
```

## 核心知识点（对应代码编号）

### ① include guard（头文件防护）

`#ifndef / #define / #endif` 三行合起来的意思：
> 如果没定义过 `__KVSTORE_HPP__`，就定义它并展开下面内容；下次再包含直接跳过。

**为什么需要？** 头文件可能被多个 `.cpp` 间接包含（比如 a.h → b.h → kvstore.hpp，c.h → kvstore.hpp），没有防护会导致重复定义报错。

**现代写法对比：**
- 老式：`#ifndef __KVSTORE_HPP__ / #define __KVSTORE_HPP__ / ... / #endif`
- 新式：`#pragma once`（一行搞定，但老编译器不支持）

面试能说出区别即可，两种都可以。

---

### ② C++ 风格头文件

为什么用 `<cstdio>` 而不是 `<stdio.h>`？

C++ 把 C 标准头文件改成了 `<cxxx>` 形式：
- 去掉 `.h`
- 加 `c` 前缀
- 内容放进 `std` 命名空间

比如 `<cstring>` 里的 `strlen` 全名是 `std::strlen`。用 C++ 风格头文件是规范做法；用 `<stdio.h>` 也能编译，但那是"C 的用法"。

---

### ③ #define 宏做编译期开关

`#define ENABLE_ARRAY_KVENGINE 1` 本质是**文本替换**：编译前预处理阶段，把代码里出现的 `ENABLE_ARRAY_KVENGINE` 全部替换成 `1`。

**宏 vs const/constexpr：**

| 特性 | `#define` | `const` / `constexpr` |
|---|---|---|
| 有类型 | ❌ 无类型，纯文本替换 | ✅ 有类型检查 |
| 发生时机 | 编译前预处理 | 编译时 |
| 可用于条件编译 | ✅ 配 `#if` 让代码不参与编译 | ❌ 代码永远参与编译 |

**关键用途：** 后续写 `#if ENABLE_ARRAY_KVENGINE ... #endif` 时，`0` 的代码块直接消失，连语法检查都不做——这就是"宏切换引擎/网络层"的原理。

---

### ④ struct 的类内默认初始化

`int fd = -1;` 这种写法：C++11 起，结构体成员可以**在声明处直接给初值**，构造对象时自动使用，避免"忘记初始化"的未定义行为。

C 语言不行，只能在构造函数或 `memset` 里初始化——这就是 C++ 写起来更安全的地方之一。

---

### ⑤ 函数指针 + using 类型别名

**读法：** `int (*Callback)(int fd)` 从变量名往外读：
- `(*ptr)`：ptr 是指针
- `(*ptr)(int fd)`：解引用后是个函数，入参 `int fd`，返回 `int`

所以它是一个"指向参数为 int、返回 int 的函数"的指针。

**`using` vs `typedef`：**
```cpp
using Callback = int (*)(int fd);    // C++11 写法，更清晰
typedef int (*Callback)(int fd);     // 老式写法，等价
```

**为什么回调用函数指针而不是直接调用？**
因为**网络层不知道协议层长什么样**——epoll 只负责"这个 fd 可读了，你去处理"，具体处理逻辑是注册时绑定的。这就是你在 tinywebserver m2 学的**回调（IoC 反转控制）**，现在换成 C 风格的函数指针版。

**对比 std::function：**
- `std::function` 更灵活（支持 lambda、捕获）
- 但热路径上有额外开销（可能堆分配、虚调用）
- **单线程事件循环的高频回调用裸函数指针更省**

---

### ⑥ 引擎结构设计

`ArrayItem` 存一对 key/value；`Array` 存"指向连续内存的指针 + 已用个数"。

**为什么 `table` 是 `ArrayItem*` 而不是 `ArrayItem[1024]`？**
为了**把内存分配推迟到运行时**（`create` 时 `new[]`），这样数组大小可以用宏/常量控制，销毁时统一释放。这是"堆上动态分配"的经典模式。

---

### ⑦ constexpr 编译期常量

`constexpr int KVS_ARRAY_SIZE = 1024;` 是编译期常量，有类型（`int`），比 `#define KVS_ARRAY_SIZE 1024` 安全（宏无类型、无作用域）。

**什么是常量表达式？**
所谓常量表达式，指的就是由多个（≥1）常量组成的表达式。换句话说，如果表达式中的成员都是常量，那么该表达式就是一个常量表达式。这也意味着，常量表达式一旦确定，其值将无法修改。

**实际开发中的例子：** 定义数组时，数组长度必须是常量表达式：

```cpp
int url[10];        // ✅ 正确，10 是常量
int url[6 + 4];     // ✅ 正确，6+4 是常量表达式
int length = 6;
int url[length];    // ❌ 错误，length 是变量
```

**constexpr 的作用：**
C++11 标准提供 `constexpr` 关键字，使指定的常量表达式获得在程序**编译阶段**计算出结果的能力，而不必等到程序运行阶段。

```cpp
constexpr int size = 1024;    // 编译期就能算出值
int arr[size];                // 可以用于数组大小
```

**constexpr vs const：**
- `const`：运行时只读，值不一定在编译期知道
- `constexpr`：编译期就能算出值，保证编译期计算

---

### ⑧ extern 声明

`extern Array g_array;` 声明"存在一个全局变量 `g_array`，定义在某个 .cpp 里"。

**头文件里只能声明不能定义**——如果定义了，多个 .cpp 包含就会重复定义链接错误。

**声明 vs 定义：**
- **声明**：不分配内存，只是告诉编译器"这个东西存在，类型是这样的"
- **定义**：分配内存，真正创建变量

---

#### extern 的深入理解

**extern 的两个作用：**

**作用一：声明外部变量/函数**
```cpp
// 在 test1.h 中
extern char g_str[];    // 声明全局变量 g_str
void fun1();
```

```cpp
// 在 test1.cpp 中
#include "test1.h"
char g_str[] = "123456";    // 定义全局变量 g_str
void fun1() { cout << g_str << endl; }
```

其他文件想使用 `g_str`，只要 `#include "test1.h"` 即可。

**作用二：extern "C" —— 指定 C 链接规则**

C++ 为了支持函数重载，会对函数名进行" name mangling"（名字修饰），比如 `int fun(int a, int b)` 可能被编译成 `fun@aBc_int_int#%$` 这样的名字。

而 C 语言不支持重载，不做 name mangling。如果在 C++ 代码里调用 C 库函数，链接时会找不到——因为 C++ 编译器去找的是 mangled 后的名字，而 C 库里的函数名是原始的。

**解决方法：**
```cpp
#ifdef __cplusplus
extern "C" {
#endif
    // 这里面的函数按 C 规则编译，不做 name mangling
    void c_function(int a, int b);
#ifdef __cplusplus
}
#endif
```

**常见坑：extern 变量声明格式不匹配**

在一个源文件里定义了数组：
```cpp
char a[6];
```

在另外一个文件里声明：
```cpp
extern char *a;    // ❌ 错误！
```

**为什么错？** 因为"指向类型 T 的指针"并不等价于"类型 T 的数组"。`extern char *a` 声明的是一个指针变量，而实际定义的是数组，两者内存布局完全不同，运行时会非法访问。

**正确写法：**
```cpp
extern char a[];    // ✅ 声明为数组
```

### ⑨ 接口为什么是全局函数而不是 class 成员函数？

课程第一版刻意用 C 风格的全局函数（`kvs_array_set(Array*, ...)`），把"数据结构"和"操作函数"分开。

**好处：** 后面换引擎（hash/rbtree）时接口签名完全一致，**适配层就能用同一套调用方式**。

**演进路径：** 等你写够 3 个引擎、感受到重复后，再升级成抽象基类（虚函数）或函数指针表——那时候你就懂为什么课程问"设计模式"了。

> **方法论：先写重复的代码，再谈抽象。** 你先感受到痛，重构时才知道为什么要抽象。

---

### ⑩ const char* 返回值

`kvs_array_get` 返回 `const char*`：告诉调用方"这个指针指向的数据你只能读、不能改"。

**为什么返回指针而不是拷贝一份？**
- **零拷贝**：性能好
- 代价：调用方不能修改它（否则破坏引擎内部数据）

这就是 **const 正确性（const correctness）**，C++ 面试常考点。

## 深入讨论：为什么用 struct 不用 class？

> 这是对话中你问的问题，也是 C++ 里经常被"过度纠结"的点。

### 一、语言本质：struct 和 class 几乎是同一个东西

C++ 设计者把 C 的 struct 扩展成了"可以有成员函数、继承、多态"的完整类类型。`class` 只是另一个关键字，**唯一的区别就两点**：

| 特性 | `struct` | `class` |
|---|---|---|
| 默认成员访问权限 | `public` | `private` |
| 默认继承方式 | `public` 继承 | `private` 继承 |

就这。除此之外语法完全一样。

---

### 二、社区惯例：什么时候用 struct，什么时候用 class？

不是语法强制，是**设计哲学**：

- **struct = 数据聚合体（plain data）**
  - 只有数据，没有行为，或者行为极少
  - 不保护内部状态，谁都能读写它的字段

- **class = 抽象数据类型（ADT）**
  - 数据 + 绑定在数据上的行为
  - 通过 `private` 隐藏内部状态、`public` 暴露受控接口
  - **保护不变式（invariant）**

**什么是"不变式"？**
一段"任何时候都必须为真"的规则。比如"银行账户余额不能为负"，这时候你必须用 class：把 `balance` 设成 private，只通过 `withdraw()` 修改，在函数里做检查。如果你用 struct，`balance` 公开，外部代码随手 `acc.balance -= 99999`，不变式就被破坏了。

> **没有不变式要保护的数据，用 struct 就够了。**

---

### 三、回到这个项目：为什么全是 struct

看一下我们的三个类型：

```cpp
struct ConnItem { int fd; char rbuffer[512]; ... };   // 纯状态，操作在 epoll 层
struct ArrayItem { char *key; char *value; };          // 一对字符串，无行为
struct Array { ArrayItem *table; int idx; };          // 一块连续内存 + 个数
```

它们都是**纯数据容器，没有"任何时候必须成立"的内部规则**——`table` 允许指向任意地址，`idx` 允许任意改。所有的操作（`kvs_array_set` 等）是全局函数，而不是成员函数。

**另外两个现实原因：**

1. **课程原版是纯 C**，没有 class。你用 struct 写，和课程代码、和别人的笔记**能逐行对照**，不会因为语法差异对不上。

2. **Linux 高性能代码的惯例就是 struct + 全局函数**：Redis、Nginx 都是这种风格。你以后读 Redis 源码，满眼都是 `struct redisObject` + `robjCreate()` 这种写法。

---

### 四、什么时候这个项目该升级成 class？

**当你需要"多个引擎共用一套接口"的时候**——也就是路线图第 6 步（array → hash → rbtree → skiptable 都写完，感受了重复代码之后）。

那时候你会想：能不能让 `Array`、`Hash`、`RBTree` 都能被同一段代码调用？答案是**抽象基类 + 虚函数**，那就必须上 class 了：

```cpp
class KVEngine {                       // 抽象基类：定义统一接口
public:
    virtual ~KVEngine() = default;
    virtual int  set(const char *key, const char *value) = 0;  // 纯虚函数
    virtual const char *get(const char *key) = 0;
    // ...
};

class ArrayEngine : public KVEngine {  // 具体引擎实现接口
    int set(const char *key, const char *value) override;
private:
    ArrayItem *table_;                 // 私有，外部不能乱改，保护不变式
    int idx_;
};
```

到这一步，`private`、`override`、多态这些 C++ 特性才真正"有用"——因为你需要隐藏内部状态、用统一指针调用不同实现。

---

### 一句话总结

> **数据用 struct，带不变式/需要多态时用 class。**
>
> 这个项目现在全是纯数据，用 struct 最诚实；等你写完 3 个引擎、感受到重复，class + 虚函数会成为"你自己想出来的改进"，而不是别人硬塞给你的语法。

这也是课程故意的设计：先让你写重复的 struct + 全局函数，你自己体会到痛，再上 class——那时候"为什么要用 class"你就真懂了，而不是背出来的。
