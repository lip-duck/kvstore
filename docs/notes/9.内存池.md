# 第 9 步：内存池

> 一次性申请一大块内存，自己管理小块分配。
> 避免频繁 new/delete 的系统调用开销和内存碎片。

---

## 为什么需要内存池？

现在代码里每插入一个 KV 就要 `new` 一个节点、`new[]` key、`new[]` value。压测时每秒几千次 `new/delete`，每次都是系统调用，开销很大，还会产生内存碎片。

**内存池的思路：** 一次性从系统申请一大块内存，自己管理小块分配。`mp_alloc` 和 `mp_free` 只是指针操作，O(1)，不进内核。

```
没有内存池：  128 次 malloc → 128 次系统调用
有内存池：    1 次 malloc  + 128 次指针操作
```

## 模板代码

### 头文件 `kvstore_mp.hpp`

```cpp
#ifndef KVSTORE_MP_HPP
#define KVSTORE_MP_HPP

#include <cstdlib>
#include <cstring>

#define MEM_PAGE_SIZE  4096   // 一页 4KB

struct MemPool {
    int   block_size;    // 每个块多大
    int   free_count;    // 还剩多少块
    char *free_ptr;      // free list 的头指针
    char *mem;          // 整块内存的起始地址（destroy 时释放）
};

int  mp_init(MemPool *m, int size);
void mp_destroy(MemPool *m);
void *mp_alloc(MemPool *m);
void  mp_free(MemPool *m, void *ptr);

#endif
```

### 实现 `kvstore_mp.cpp`

```cpp
#include "kvstore_mp.hpp"

// 全局内存池（给 RbNode 用）
MemPool g_rbnode_pool;

int mp_init(MemPool *m, int size) {
    if (!m) return -1;
    if (size < 16) size = 16;          // 块不能太小，至少能存一个指针 + 对齐

    m->block_size = size;

    // 一次性申请一整页
    m->mem = (char *)malloc(MEM_PAGE_SIZE);
    if (!m->mem) return -1;

    m->free_ptr  = m->mem;
    m->free_count = MEM_PAGE_SIZE / size;

    // 把所有小块串成 free list
    // 每个空闲块的前 8 个字节，存"下一个空闲块"的地址
    char *ptr = m->free_ptr;
    for (int i = 0; i < m->free_count; i++) {
        *(char **)ptr = ptr + size;
        ptr += size;
    }
    *(char **)ptr = nullptr;

    return 0;
}

void mp_destroy(MemPool *m) {
    if (!m || !m->mem) return;
    free(m->mem);       // 一次性释放整块
    m->mem = nullptr;
    m->free_ptr = nullptr;
    m->free_count = 0;
}

void *mp_alloc(MemPool *m) {
    if (!m || m->free_count == 0) return nullptr;

    void *ptr = m->free_ptr;           // 拿走链表头
    m->free_ptr = *(char **)ptr;       // free_ptr 后移一块
    m->free_count--;
    return ptr;
}

void mp_free(MemPool *m, void *ptr) {
    if (!m || !ptr) return;

    // 把块挂回链表头
    *(char **)ptr = m->free_ptr;       // 被释放的块 → 指向旧的链表头
    m->free_ptr = (char *)ptr;         // 链表头 = 这个块
    m->free_count++;
}
```

## 核心知识点

### free list 怎么串？

最关键的一行：
```cpp
*(char **)ptr = ptr + size;
```

**内存布局：** 一页 4096 字节，切成 128 个 32 字节的块：

```
块0 (0~31)    块1 (32~63)    块2 (64~95)    ...
┌──────────┐  ┌──────────┐  ┌──────────┐
│ next=块1 │  │ next=块2 │  │ next=块3 │
└──────────┘  └──────────┘  └──────────┘
```

**技巧：** 块在空闲时，它的前 8 个字节没有别的用，干脆用来存"下一个空闲块在哪"。

```cpp
ptr            // 指向块0 的起始地址
(char **)ptr   // 把块0 的起始地址看成 char* 类型的指针
*(char **)ptr  // 往块0 的前 8 个字节写一个地址
       = ptr + size;  // 写的是"下一块的地址"
```

### mp_alloc：摘一块

```
分配前：  free_ptr → [块0] → [块1] → [块2] → ...
分配后：  free_ptr → [块1] → [块2] → ...
          返回 块0
```

### mp_free：挂回去

```
释放块1：
释放前：  free_ptr → [块2] → ...
释放后：  free_ptr → [块1] → [块2] → ...
```

**LIFO（后进先出）**，后释放的块下次先被分配。

## 深入讨论：为什么最小块是 16？

### 不是 4 字节，是 8 字节

在 64 位系统上，**指针是 8 字节**，不是 4 字节。free list 需要在每个空闲块的开头存一个指针，所以块至少要 8 字节。

### 为什么取 16 而不是 8？——内存对齐

```
假设 block_size = 8：

mem:  [块0] [块1] [块2] [块3] ...
地址:  0     8    16    24

块0 起始地址 = 0   → 16 对齐 ✓
块1 起始地址 = 8   → 不是 16 对齐 ✗
块2 起始地址 = 16  → 16 对齐 ✓
```

x86-64 系统上，`malloc` 保证返回的地址是 **16 字节对齐**的。如果块大小是 8，第二个块的起始地址就不对齐了。

```
block_size = 16：

mem:  [块0]  [块1]  [块2]  [块3] ...
地址:  0      16     32     48

每个块起始地址都是 16 的倍数 → 全部对齐 ✓
```

**对齐有什么用？** 如果块里存了 `double`（8 字节）或 `long long`，对齐访问只需要一条指令，不对齐可能要两条指令拼。保持 16 字节对齐最安全。

> 8 字节是"能存下指针"的最低要求；16 字节是"保证每个块起始地址都对齐"的要求。

## 深入讨论：怎么接入项目？

### 之前：全部用 new/delete

```cpp
// 创建节点
RbNode *node = new RbNode;
node->key = new char[strlen(key) + 1]();
node->value = new char[strlen(value) + 1]();

// 删除节点
delete[] node->value;
delete[] node->key;
delete node;
```

### 之后：节点走内存池，key/value 还是 new

```cpp
// 创建节点
RbNode *node = (RbNode *)mp_alloc(&g_rbnode_pool);   // 从池拿
node->key = new char[strlen(key) + 1]();             // key 变长，还是 new[]
node->value = new char[strlen(value) + 1]();         // value 变长，还是 new[]

// 删除节点
delete[] node->value;
delete[] node->key;
mp_free(&g_rbnode_pool, node);                       // 节点还给池
```

### 为什么 `delete node` 不能用了？

因为 `mp_alloc` 返回的内存**不是 `new` 出来的**：

```
new RbNode      → 调用 operator new → 内核分配 → 必须用 delete 还回去
mp_alloc(...)   → 从内存池切一块    → 不进内核     → 必须用 mp_free 还回去
```

如果对 `mp_alloc` 返回的指针调 `delete`：
1. `delete` 会调用析构函数，然后调 `free(node)` 把内存还给系统
2. **但这块内存本来就是内存池那一整块里的一小片，不是独立 malloc 的**
3. `free` 一个不是 malloc 返回的地址 → **程序直接崩溃**

必须用 `mp_free`：它不把内存还给系统，只是把这个块**挂回 free list**，下次 `mp_alloc` 还能用。

### 哪些走池，哪些不走？

| 内存 | 怎么分配 | 怎么释放 | 为什么 |
|---|---|---|---|
| RbNode 本身 | `mp_alloc` | `mp_free` | 固定大小，适合内存池 |
| key（变长字符串） | `new char[]` | `delete[]` | 长度不固定，不适合固定块池 |
| value（变长字符串） | `new char[]` | `delete[]` | 同上 |

**规律：固定大小的对象走内存池，变长字符串继续用 new/delete。**

> `new`/`delete` 和 `mp_alloc`/`mp_free` 是两套独立的内存管理，不能混用。

## 深入讨论：常见编译错误

### undefined reference to `g_rbnode_pool`

头文件写了 `extern MemPool g_rbnode_pool;` 但没在 .cpp 里定义：

```cpp
// kvstore_mp.cpp 里加一行
MemPool g_rbnode_pool;   // 定义：真正分配内存
```

| 写法 | 位置 | 作用 |
|---|---|---|
| `extern MemPool g_rbnode_pool;` | 头文件 | 声明：告诉所有 .cpp "有这么个变量" |
| `MemPool g_rbnode_pool;` | 某个 .cpp | 定义：真正分配内存创建这个变量 |

一个变量只能定义一次，但可以在多个头文件里 extern 声明。

## 测试

```cpp
// test_mp.cpp
#include <cstdio>
#include "kvstore_mp.hpp"

int main() {
    MemPool m;
    mp_init(&m, 32);

    void *p1 = mp_alloc(&m);
    void *p2 = mp_alloc(&m);
    void *p3 = mp_alloc(&m);
    printf("p1=%p\np2=%p\np3=%p\n", p1, p2, p3);

    mp_free(&m, p2);              // 释放 p2
    void *p4 = mp_alloc(&m);      // 应该拿回 p2
    printf("p4=%p (应该等于 p2)\n", p4);

    mp_destroy(&m);
    return 0;
}
```

```bash
g++ -std=c++11 kvstore_mp.cpp test_mp.cpp -o test_mp
./test_mp
```

预期：`p4 == p2`，证明 free list 正常工作。
