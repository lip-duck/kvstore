# 第 6 步：kvstore_hash.cpp 哈希引擎

> array 引擎的问题：查找是 O(n)，1024 个 key 要遍历 1024 次。
>
> hash 表的优势：查找 O(1)，key 通过哈希函数直接定位到桶，平均只查一次。
>
> 这一步实现链地址法哈希表，并在协议层加 HSET/HGET 等 5 条命令。

---

## 为什么先做 hash？

| 对比 | array 引擎 | hash 引擎 |
|---|---|---|
| 数据结构 | 一块连续数组 | 桶数组 + 链表 |
| 查找 | O(n) 线性遍历 | O(1) 平均（哈希定位 + 短链表） |
| 插入 | O(1) 追加 | O(1) 头插 |
| 删除 | O(n) 查找 + 交换 | O(1) 平均 |
| 冲突 | 无（key 唯一） | 有（链地址法解决） |
| 适用场景 | 数据量小、按序遍历 | 数据量大、快速查找 |

这一步你会：
1. 写一个链地址法哈希表
2. 在协议层加 5 条 HSET/HGET 命令
3. **感受命令从 5 条变 10 条，switch 开始变长了**——为第 7 步重构埋伏笔

## 模板代码

### A：头文件改动

在 `kvstore.hpp` 里加 hash 引擎的声明：

```cpp
// ---------------- hash 引擎 ----------------
constexpr int KVS_HASH_SIZE = 1024;

struct HashItem {
    char *key = nullptr;
    char *value = nullptr;
    HashItem *next = nullptr;     // ① 链表指针：解决哈希冲突
};

struct Hash {
    HashItem *buckets[KVS_HASH_SIZE] = {nullptr};  // ② 桶数组，每个桶是一条链表
    int count = 0;                                  // 元素总数
};

extern Hash g_hash;              // ③ 第二个全局引擎实例

// hash 引擎接口
int  kvstore_hash_create(Hash *h);
void kvstore_hash_destroy(Hash *h);
int  kvs_hash_set(Hash *h, const char *key, const char *value);
const char *kvs_hash_get(Hash *h, const char *key);
int  kvs_hash_delete(Hash *h, const char *key);
int  kvs_hash_modify(Hash *h, const char *key, const char *value);
int  kvs_hash_count(Hash *h);
```

### B：新建 `kvstore_hash.cpp`

```cpp
// ============================================================
// kvstore_hash.cpp —— hash 引擎：链地址法哈希表
// 查找 O(1) 平均，冲突时沿链表遍历
// ============================================================
#include "kvstore.hpp"

Hash g_hash;

// ④ 哈希函数：除留余数法 + 简单散列
static int hash_func(const char *key) {
    unsigned int h = 0;
    while (*key) {
        h = h * 31 + (unsigned char)(*key++);   // 乘 31 是经典做法（字符串散列）
    }
    return h % KVS_HASH_SIZE;
}

int kvstore_hash_create(Hash *h) {
    if (!h) return -1;
    // buckets 数组已经在 struct 里默认初始化为 nullptr
    h->count = 0;
    return 0;
}

void kvstore_hash_destroy(Hash *h) {
    if (!h) return;
    for (int i = 0; i < KVS_HASH_SIZE; i++) {
        HashItem *item = h->buckets[i];
        while (item) {
            HashItem *next = item->next;
            delete[] item->key;
            delete[] item->value;
            delete item;              // ⑤ HashItem 本身也是 new 出来的
            item = next;
        }
        h->buckets[i] = nullptr;
    }
    h->count = 0;
}

// ⑥ set：先查有没有，有就改 value，没有就头插
int kvs_hash_set(Hash *h, const char *key, const char *value) {
    if (!h || !key || !value) return -1;

    int idx = hash_func(key);

    // 先查链表，key 已存在就直接改 value
    HashItem *item = h->buckets[idx];
    while (item) {
        if (strcmp(item->key, key) == 0) {
            delete[] item->value;
            item->value = new char[strlen(value) + 1]();
            strcpy(item->value, value);
            return 0;
        }
        item = item->next;
    }

    // 不存在，新建节点，头插到桶里
    HashItem *newitem = new HashItem;
    newitem->key = new char[strlen(key) + 1]();
    newitem->value = new char[strlen(value) + 1]();
    strcpy(newitem->key, key);
    strcpy(newitem->value, value);
    newitem->next = h->buckets[idx];      // ⑦ 头插法
    h->buckets[idx] = newitem;
    h->count++;
    return 0;
}

const char *kvs_hash_get(Hash *h, const char *key) {
    if (!h || !key) return nullptr;
    int idx = hash_func(key);
    HashItem *item = h->buckets[idx];
    while (item) {
        if (strcmp(item->key, key) == 0) return item->value;
        item = item->next;
    }
    return nullptr;
}

int kvs_hash_delete(Hash *h, const char *key) {
    if (!h || !key) return -1;
    int idx = hash_func(key);
    HashItem *item = h->buckets[idx];
    HashItem *prev = nullptr;

    while (item) {
        if (strcmp(item->key, key) == 0) {
            // ⑧ 链表删除：改前驱指针
            if (prev) prev->next = item->next;
            else      h->buckets[idx] = item->next;   // 删的是头节点
            delete[] item->key;
            delete[] item->value;
            delete item;
            h->count--;
            return 0;
        }
        prev = item;
        item = item->next;
    }
    return h->count;    // 找不到，返回 >0
}

int kvs_hash_modify(Hash *h, const char *key, const char *value) {
    if (!h || !key || !value) return -1;
    int idx = hash_func(key);
    HashItem *item = h->buckets[idx];
    while (item) {
        if (strcmp(item->key, key) == 0) {
            delete[] item->value;
            item->value = new char[strlen(value) + 1]();
            strcpy(item->value, value);
            return 0;
        }
        item = item->next;
    }
    return h->count;
}

int kvs_hash_count(Hash *h) {
    if (!h) return -1;
    return h->count;
}
```

## 核心知识点（对应代码编号）

### ① 为什么 HashItem 有 next 指针？

**哈希冲突：** 两个不同的 key 算出来同一个哈希值（`h % KVS_HASH_SIZE` 相同）。

```
key1 = "Apple"   → 哈希值 = 356
key2 = "Banana"  → 哈希值 = 356   ← 冲突了！
```

**解决办法：链地址法。** 每个桶里挂一条链表，冲突的 key 都挂在这条链上。查 key 的时候，先定位到桶，再沿链表逐个 strcmp。

```
桶 356:
  ┌──────┐     ┌──────┐
  │Apple │ ──→ │Banana│ ──→ NULL
  └──────┘     └──────┘
```

---

### ② 桶数组

`buckets[1024]` 就是 1024 个桶，每个桶是一条链表的头指针。

key 哈希到哪个桶，就往哪个桶的链表里插。

**负载因子：** 元素总数 / 桶数。1024 个桶存 1024 个元素，平均每个桶 1 个节点，冲突概率低。如果存了 10000 个元素，平均每个桶 10 个节点，查找就变慢了——这时候需要扩容。

---

### ④ 哈希函数

```cpp
h = h * 31 + (unsigned char)(*key++);
```

这是 Java `String.hashCode()` 的经典写法。乘 31 是因为它是个奇质数，散列分布更均匀，冲突少。

**最后 `% KVS_HASH_SIZE`** 把这个大数压缩到 0~1023 的范围，对应桶数组下标。

---

### ⑤ HashItem 本身也是 new 出来的

和 array 引擎不同：
- **array**：一块连续的大内存（table[1024]），一次性分配
- **hash**：每个节点单独 new

所以 destroy 时要：
1. 先 `delete[] item->key` 和 `delete[] item->value`（字符串）
2. 再 `delete item`（节点本身）

---

### ⑥ set 的逻辑：upsert

先查链表——key 存在就改 value，不存在才新建节点。

这和 array 的"只追加"不一样：
- array.set：永远追加，重复 key 会有两份
- hash.set：存在就更新（update），不存在就插入（insert）= **upsert**

---

### ⑦ 头插法

新节点插到链表头部，O(1)。

```
新节点 → 旧头节点 → 旧第二个 → ...
```

尾插要遍历到尾部，O(n)。教学用头插，简单快。

---

### ⑧ 链表删除

单链表删除要知道前驱节点（prev），所以遍历的时候要记着 prev。

两种情况：
- **删头节点**：`h->buckets[idx] = item->next`
- **删中间/尾节点**：`prev->next = item->next`

这是链表的基本功。

## 深入讨论：哈希函数

### 一、当前的哈希函数够不够用？

```cpp
static int hash_func(const char *key) {
    unsigned int h = 0;
    while (*key) {
        h = h * 31 + (unsigned char)(*key++);
    }
    return h % KVS_HASH_SIZE;
}
```

**教学项目完全够用。** 对于随机分布的 key（比如 "Name"、"Age"、"Name1"、"Name2"...），分布还算均匀，1024 个桶里冲突率不高。

---

### 二、什么时候需要换？

两个场景：

**场景 1：冲突率太高**
如果你的 key 都是有规律的（比如 "key1", "key2", "key3"...），乘 31 散列可能会让它们聚集在少数几个桶里。这时候查一个 key 要在链表里遍历很长。

**场景 2：防哈希碰撞攻击**
恶意攻击者知道你用的哈希函数后，可以构造一批 key，让它们全部哈希到同一个桶——你的 O(1) 查找退化成 O(n) 链表遍历，服务器直接被打满。这就是著名的"哈希拒绝服务攻击"（HashDoS）。

---

### 三、更好的哈希函数有哪些？

| 算法 | 特点 | 适用场景 |
|---|---|---|
| 乘 31（Java hashCode） | 简单、经典 | 教学、一般场景 |
| djb2 | 分布更均匀、最常用的字符串哈希 | 生产环境首选 |
| FNV-1a | 简单、快、分布好 | 嵌入式、轻量级 |
| MurmurHash3 | 分布极好、雪崩效应好 | 高性能、防碰撞攻击 |

**djb2 示例：**
```cpp
static int hash_func(const char *key) {
    unsigned long h = 5381;
    while (*key) {
        h = ((h << 5) + h) + (unsigned char)(*key++);  // h * 33 + c
    }
    return h % KVS_HASH_SIZE;
}
```

**我的建议：** 现在不用换。等你做完项目、想优化的时候，把这一行换掉就行——这就是哈希表的好处：**哈希函数可以独立替换，不影响其他代码**。

## 深入讨论：C 语言字符串操作

### 一、为什么 `strcpy` 而不是 `=`？

```cpp
item->value = value;        // ❌ 这不是复制字符串！
strcpy(item->value, value); // ✅ 这才是复制内容
```

**因为 `=` 赋值的是指针，不是字符串内容。**

```
item->value = value 做的事：
两个指针指向同一块内存：

value → ┌─────────────┐
        │  K  i  n  g │  ← 同一块内存
        └─────────────┘
item->value ↗
```

**问题：**
1. 调用方的 value 可能随时被覆盖或释放
2. destroy 的时候会 double free
3. 你不知道这块内存什么时候会变

---

### 二、strcpy 做了什么？

`strcpy` 逐个字符地把字符串内容**复制**到新分配的内存里：

```
第 1 步：先 new 一块新内存
item->value → ┌─────────────┐
               │ ? ? ? ? ? ? │  ← 新分配的空内存
               └─────────────┘

value → ┌─────────────┐
        │  K  i  n  g │  ← 原始字符串
        └─────────────┘

第 2 步：strcpy 逐个字符拷贝
item->value → ┌─────────────┐
               │  K  i  n  g │  ← 内容复制过来了
               └─────────────┘

value → ┌─────────────┐
        │  K  i  n  g │  ← 原始字符串还在，两块内存独立
        └─────────────┘
```

**现在是两块独立的内存，各存一份 "King"。**

---

### 三、完整的正确流程

```cpp
// ① 先 new 一块新内存，大小正好能装下 value 字符串
item->value = new char[strlen(value) + 1]();

// ② 再把字符串内容复制过去
strcpy(item->value, value);
```

为什么要两步？
- `new char[n]` 只是要了一块空内存，里面是垃圾值
- `strcpy` 才把真正的内容写进去

**缺了第①步，strcpy 不知道往哪写**（野指针）。
**缺了第②步，新内存里是垃圾值**（不是字符串）。

---

### 四、对比：`=` vs `strcpy`

| 写法 | 做了什么 | 两个指针 | 内存关系 |
|---|---|---|---|
| `item->value = value;` | 复制指针地址 | 指向同一块内存 | 浅拷贝 |
| `strcpy(item->value, value);` | 复制字符串内容 | 指向两块不同内存 | 深拷贝 |

---

### 五、为什么 C++ 里不用 `=`？

因为 C 语言**没有字符串类型**。所谓"字符串"就是 `char*` 指向的一块内存，以 `\0` 结尾。

C++ 如果你用 `std::string`，就可以直接 `=` 了：

```cpp
std::string a = "King";
std::string b = a;     // ✅ 这才是真正的"赋值"，自动复制内容
```

因为 `std::string` 重载了 `=` 运算符，内部做了深拷贝。

但课程用的是 C 风格 `char*`，没有这个运算符重载，所以你得手动用 `strcpy`。

## 深入讨论：遍历字符串 `while (*key)`

### 一、为什么是 `while (*key)`，不是 `while (key)`？

```cpp
while (*key) {          // ✅ 对：判断"当前字符"是不是 '\0'
while (key) {           // ❌ 错：判断"指针本身"是不是 nullptr
```

如果写成 `while (key)`，只要这个指针不是空指针（它永远不是），循环就**永远停不下来**，直接越界访问内存。

---

### 二、`*key` 到底在判断什么？

`key` 是 `const char*` 类型——一个指向字符的指针。

```
key 是个指针，存的是地址：
   key
    │
    ▼
  ┌───┬───┬───┬───┬────┐
  │ N │ a │ m │ e │ \0 │
  └───┴───┴───┴───┴────┘
```

- `key`：指针本身，存的是地址
- `*key`：指针指向的那个字符（第一次是 `'N'`）

**C 语言的字符串规则：** 字符串永远以 `'\0'`（ASCII 值为 0）结尾。

**C 语言的真假规则：** 0 就是 false，非 0 就是 true。

所以 `while (*key)` 的意思是：
> 只要当前字符不是 `'\0'`（非 0，true），就继续循环。

---

### 三、指针是怎么一步步移动的？

假设 key 指向 `"Name"`：

| 轮次 | `*key` | 操作 |
|---|---|---|
| 1 | `'N'` (78) | 计算 h，然后 key++ |
| 2 | `'a'` (97) | 计算 h，然后 key++ |
| 3 | `'m'` (109) | 计算 h，然后 key++ |
| 4 | `'e'` (101) | 计算 h，然后 key++ |
| 5 | `'\0'` (0) | 退出循环 |

---

### 四、等价写法

`while (*key)` 完全等价于：

```cpp
while (*key != '\0') {    // 明确写出来
while (*key != 0) {       // '\0' 就是 0
```

C 程序员习惯省略 `!= '\0'`，因为更短。这是一种惯用写法。

---

### 五、完整计算过程

```cpp
const char *key = "Name";
unsigned int h = 0;

while (*key) {
    h = h * 31 + (unsigned char)(*key++);
}
```

| 轮次 | `*key` | `key++` 后 | h 值 |
|---|---|---|---|
| 1 | `'N'` (78) | 指向 'a' | 0*31 + 78 = 78 |
| 2 | `'a'` (97) | 指向 'm' | 78*31 + 97 = 2515 |
| 3 | `'m'` (109) | 指向 'e' | 2515*31 + 109 = 78074 |
| 4 | `'e'` (101) | 指向 '\0' | 78074*31 + 101 = 2420395 |
| 5 | `'\0'` (0) | — | 退出循环 |

最后 `return h % KVS_HASH_SIZE;` 把这个大数压缩到 0~1023 的范围。
