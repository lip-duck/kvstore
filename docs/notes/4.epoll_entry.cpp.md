# 第 4 步：epoll_entry.cpp 网络层

> 这一步把前三步串成真正能联网的服务器，也是你 tinywebserver reactor 经验直接迁移过来的地方。
>
> 模型：单线程 Reactor —— epoll_wait 等就绪事件 → 根据 fd 找到连接对象 → 调回调。

---

## 模板代码

```cpp
// ============================================================
// epoll_entry.cpp —— epoll 网络层（单线程 Reactor）
// 模型：epoll_wait 等就绪事件 → 根据 fd 找到连接对象 → 调回调
// ============================================================
#include "kvstore.hpp"

#include <sys/socket.h>
#include <sys/epoll.h>
#include <netinet/in.h>
#include <unistd.h>
#include <fcntl.h>
#include <string.h>
#include <stdio.h>
#include <errno.h>

#define MAX_EVENTS 1024
#define MAX_CONNS  1048576          // ① 最多支持 100w 连接

static int epfd = -1;
static ConnItem connlist[MAX_CONNS];  // ② fd 直接当下标

static int accept_cb(int fd);
static int recv_cb(int fd);
static int send_cb(int fd);

// ③ 注册/修改 epoll 事件
static void set_event(int fd, uint32_t events, bool add) {
    struct epoll_event ev;
    ev.events = events;
    ev.data.fd = fd;
    if (add) epoll_ctl(epfd, EPOLL_CTL_ADD, fd, &ev);
    else     epoll_ctl(epfd, EPOLL_CTL_MOD, fd, &ev);
}

// listenfd 可读：有新连接
static int accept_cb(int fd) {
    struct sockaddr_in addr;
    socklen_t len = sizeof(addr);
    int cfd = accept(fd, (struct sockaddr*)&addr, &len);
    if (cfd < 0) return -1;

    memset(&connlist[cfd], 0, sizeof(ConnItem));
    connlist[cfd].fd = cfd;
    connlist[cfd].recv_callback = recv_cb;   // 新连接的读事件处理函数
    connlist[cfd].send_callback = send_cb;

    set_event(cfd, EPOLLIN, true);            // 先关心读
    return cfd;
}

// clientfd 可读：收到命令
static int recv_cb(int fd) {
    char *buf = connlist[fd].rbuffer;
    // ④ 留一个字节给 '\0'，防止越界
    int n = recv(fd, buf, BUFFER_LENGTH - 1, 0);
    if (n == 0) {                            // ⑤ 对端正常关闭（FIN）
        epoll_ctl(epfd, EPOLL_CTL_DEL, fd, nullptr);
        close(fd);
        return -1;
    }
    if (n < 0) return -1;

    buf[n] = '\0';                            // 字符串结尾，strtok 要用
    kvstore_request(&connlist[fd]);           // ⑥ 协议层处理，结果在 wbuffer
    connlist[fd].wlen = strlen(connlist[fd].wbuffer);

    set_event(fd, EPOLLOUT, false);          // ⑦ 切到写事件
    return n;
}

// clientfd 可写：发响应
static int send_cb(int fd) {
    int n = send(fd, connlist[fd].wbuffer, connlist[fd].wlen, 0);
    if (n < 0) return -1;
    set_event(fd, EPOLLIN, false);           // ⑧ 发完切回读
    return n;
}

// 创建监听 socket
static int init_server(unsigned short port) {
    int sfd = socket(AF_INET, SOCK_STREAM, 0);
    if (sfd < 0) return -1;

    int opt = 1;
    setsockopt(sfd, SOL_SOCKET, SO_REUSEADDR, &opt, sizeof(opt));  // ⑨ 端口复用

    struct sockaddr_in addr;
    memset(&addr, 0, sizeof(addr));
    addr.sin_family = AF_INET;
    addr.sin_addr.s_addr = htonl(INADDR_ANY);
    addr.sin_port = htons(port);

    if (bind(sfd, (struct sockaddr*)&addr, sizeof(addr)) < 0) return -1;
    if (listen(sfd, 10) < 0) return -1;
    return sfd;
}

// 主循环入口（kvstore.cpp 的 main 会调它）
int epoll_entry() {
    epfd = epoll_create1(0);

    int lfd = init_server(9096);
    connlist[lfd].recv_callback = accept_cb;  // ⑩ listenfd 也用同一个数组
    set_event(lfd, EPOLLIN, true);

    printf("kvstore listening on 0.0.0.0:9096\n");

    struct epoll_event events[MAX_EVENTS];
    while (true) {
        int n = epoll_wait(epfd, events, MAX_EVENTS, -1);
        for (int i = 0; i < n; i++) {
            int fd = events[i].data.fd;
            if (events[i].events & EPOLLIN) {
                connlist[fd].recv_callback(fd);   // ⑪ 回调分发
            } else if (events[i].events & EPOLLOUT) {
                connlist[fd].send_callback(fd);
            }
        }
    }
    return 0;
}
```

## 核心知识点（对应代码编号）

### ① 为什么数组要 1M？

`connlist[1048576]` 是静态全局数组，占 BSS 段（不占可执行文件大小）。

**目的：用 fd 当数组下标直接索引。**

Linux 的 fd 是小整数（0,1,2,3...），新连接的 fd 一定小于上限。这样找一个连接的状态是 `connlist[fd]`，O(1)。

**代价：** 数组要开够大（fd 最大可能到几百万），浪费一点内存换速度。这是"空间换时间"。

---

### ② 为什么不用 `map<int, ConnItem>`？

你可能会问：`std::map` 或 `std::unordered_map<fd, ConnItem>` 不更灵活？

可以，但：
- 哈希查找有计算开销
- fd 是连续小整数，直接索引是最快的
- 课程故意这么写，让你体会"用 fd 当下标"这种工程技巧
- 1M × sizeof(ConnItem) ≈ 1M × 1024B = 1GB 虚拟内存（BSS 按需分配物理页，实际不占那么多）

---

### ③ set_event：ADD 和 MOD 的区别

epoll_ctl 的三个操作：

| 操作 | 作用 |
|---|---|
| `EPOLL_CTL_ADD` | 第一次把 fd 加进 epoll |
| `EPOLL_CTL_MOD` | fd 已经在 epoll 里，改它关心的事件 |
| `EPOLL_CTL_DEL` | 移除 fd |

**为什么要区分？** epoll 内部用红黑树管理 fd，重复 ADD 会报错，首次必须用 ADD。

---

### ④ 防越界 bug（重要）

课程原版 `recv(fd, buf, BUFFER_LENGTH, 0)` 然后 `buf[n] = '\0'`——如果 n 正好等于 BUFFER_LENGTH，`buf[BUFFER_LENGTH]` 越界写！

**修复：** `recv(fd, buf, BUFFER_LENGTH - 1, 0)`，留一个字节专门放 `'\0'`。

这是手写网络代码的经典 bug，你写的时候注意。

---

### ⑤ recv 返回值的三种情况

| 返回值 | 含义 | 处理方式 |
|---|---|---|
| `> 0` | 收到 n 字节 | 正常处理 |
| `= 0` | 对端正常关闭（收到 FIN） | close 并从 epoll 移除 |
| `< 0` | 出错（errno 有意义） | 根据 errno 判断 |

**很多新手把 `=0` 当错误处理，这是错的。** recv 返回 0 不是错误，是对端说"我说完了"。

---

### ⑥ 分层设计：网络层不关心业务

网络层不关心"SET 是什么意思"，它只负责：
1. 把收到的数据塞进 `rbuffer`
2. 调 `kvstore_request`
3. 协议层处理完结果自然在 `wbuffer`

这就是分层：
- **网络层**：只懂收发
- **协议层**：只懂命令
- **引擎层**：只懂数据结构

---

### ⑦⑧ 事件状态切换（核心设计）

一个连接有读事件和写事件，但**不能同时监听两个**——写事件几乎总是就绪的（发送缓冲区不满），如果你一直监听 EPOLLOUT，epoll_wait 会立刻返回，CPU 100% 空转（busy loop）。

**所以设计：**
- 平时只关心 EPOLLIN（等客户端发命令）
- 收到命令、处理完有了响应数据，临时切到 EPOLLOUT（把响应发出去）
- 发完再切回 EPOLLIN（等下一条命令）

这就是"读→处理→写→读"的状态机：

```
    EPOLLIN ────收到命令────> EPOLLOUT
       ↑                        │
       └────发完响应─────────────┘
```

---

### ⑨ SO_REUSEADDR

服务器重启时，如果上一次进程的连接还在 TIME_WAIT 状态，bind 会报 "Address already in use"。

`SO_REUSEADDR` 让你立刻能重启，开发时必备。

---

### ⑩ listenfd 也用同一个数组

`connlist[lfd]` 存的是 listen socket 的状态，它的 `recv_callback` 被设成了 `accept_cb`。

主循环里不区分"这是 listenfd 还是 clientfd"，统一调 `recv_callback`——listenfd 的回调是 accept，clientfd 的回调是 recv。

**多态靠函数指针实现。**

---

### ⑪ 水平触发（LT）vs 边缘触发（ET）

| 模式 | 行为 | 要求 |
|---|---|---|
| LT（默认） | 只要缓冲区有数据，epoll_wait 就一直通知你 | 简单，一次 recv 就行 |
| ET | 状态变化时通知一次 | 必须非阻塞 + 循环读到 EAGAIN |

教学先用 LT（简单）。ET 性能更好但难写，后面优化阶段再讲。

---

## 深入讨论：epoll 核心概念

### 一、epoll 三件套

epoll 是 Linux 特有的 IO 多路复用机制，比 select/poll 高效：

1. **`epoll_create1(0)`**：创建 epoll 实例，返回 epfd（epoll 的文件描述符）
2. **`epoll_ctl(epfd, op, fd, &ev)`**：注册/修改/删除要监听的 fd
3. **`epoll_wait(epfd, events, maxevents, timeout)`**：等待事件就绪，返回就绪的事件列表

---

### 二、为什么 epoll 比 select 高效？

| 对比 | select | epoll |
|---|---|---|
| 数据结构 | 数组 | 红黑树 + 双向链表 |
| 每次调用 | 都要把 fd 集合从用户态拷贝到内核态 | 只在 epoll_ctl 时拷贝一次 |
| 查找就绪 fd | 遍历全部 fd（O(n)） | 直接返回就绪链表（O(就绪数)） |
| 最大 fd 数 | 1024（FD_SETSIZE 限制） | 无限制（受内存限制） |

---

### 三、Reactor 模式

这就是你在 tinywebserver 里学的 Reactor 模式：

```
            ┌─────────────┐
            │  epoll_wait   │  ← 事件分发器
            └───────┬───────┘
                    │ 就绪事件
        ┌───────────┼───────────┐
        ▼           ▼           ▼
    accept_cb   recv_cb    send_cb   ← 事件处理器（回调）
```

**核心思想：** 事件循环（epoll_wait）是通用的，具体怎么处理事件是可插拔的（回调函数）。这就是"控制反转"（IoC）。

---

### 四、单线程为什么够用？

这个项目是**单线程 epoll 无锁模型**：
- 所有连接的事件都在同一个线程里处理
- 不需要加锁（没有多线程竞争）
- 没有上下文切换开销

**为什么够用？** 因为每个请求的处理时间极短（内存操作，没有磁盘 IO），单线程串行处理就能打满。

**什么时候需要多线程？** 当处理慢的时候（比如数据库查询、磁盘读写），单线程会成为瓶颈。那时候才需要加线程池。
